# 安安 Stack-chan 固件设计（spec）

- 版本：v0.2 · 2026-11-12 · 状态：等用户审阅，未写代码
- 基线：`78/xiaozhi-esp32` main（读取于 2026-11-12，commit `026e9b6`），板子 `main/boards/m5stack/stackchan`
- 参考：`DogcanAmee/stackchan-xiaozhi-firmware`（旧 fork，只读参考，不再在上面开发）
- 架构页：https://claude.ai/artifact/MX42oMSSFW3WD1tzeoM7Vm

## 1. 目标

用户原话整理。冲突时排前面的优先。

1. 喊她就有反应：待机、她说话中、她刚说完，三种时候都能唤醒。
2. 待机时头不动，只有屏幕上的小动作。
3. 用户说话时她看着用户（人脸追踪只在这个状态开）。
4. 她说话时有反馈：点头、摇头，灯环配合。
5. 脸用用户自己的 21 张图，并且会动。
6. 待机时偶尔播屏幕小动作（喝咖啡、玩手机等）。

不做（YAGNI）：摸头、体感、Claude Code 桥接、通知 HTTP 服务、配网页美化。这些旧 fork 有，本次不搬。

## 2. 仓库和构建

- 新仓库：在用户 GitHub（`DogcanAmee`）下 fork `78/xiaozhi-esp32`，命名 `anan-stackchan`。如果 GitHub 因为已有同网络 fork 而拒绝，改为新建普通仓库并把官方仓库设为 `upstream` remote。
- 开发分支：`anan/main`。每个阶段一个 PR，按用户的分层评审流程走（见第 9 节）。
- 构建：官方要求 ESP-IDF ≥ 6.0.1。用仓库自带的 GitHub Actions `build.yml` 思路，加一个只编译 `m5stack/stackchan` 的 workflow，产出合并固件作为 artifact。用户下载后烧录。本地不强制装 IDF。
- 不改其他板子的任何文件。核心层（`application.*`、`audio/`）尽量不动；必须动时单独成 PR 并说明。

## 3. 部件和边界

所有新代码放在 `main/boards/m5stack/stackchan/` 下，每个部件一对 `.h/.cc`。`stackchan.cc` 只负责初始化和把部件接起来。

| 部件 | 文件 | 职责 | 依赖 |
|---|---|---|---|
| 行为协调器 | `behavior_director.{h,cc}` | 唯一决定头、脸、灯听谁的。监听设备状态和情绪，给下面的部件下命令 | 以下全部 |
| 脖子 | 已有 `ServoNeck`（从 `stackchan.cc` 拆到 `servo_neck.{h,cc}`） | 非阻塞缓动转头、限位 | 舵机总线 |
| 动作 | `head_gestures.{h,cc}` | 点头、摇头、歪头：一串关键帧，播完回到动作前的位置 | 脖子 |
| 看人 | `face_tracker.{h,cc}` | 从摄像头得到人脸位置，输出目标偏航 / 俯仰 | 摄像头 |
| 灯环 | `led_ring.{h,cc}` | 常亮、呼吸、渐暗三种效果；颜色由协调器给 | 已有 `Py32IoExpander` |
| 待机小动作 | `idle_actions.{h,cc}` | 待机计时，随机挑一个动画播一遍 | 显示 |
| 脸 | 已有 `EmoteDisplay` + 自定义素材包 | 按名字播 `.eaf` 动画 | assets 分区 |

规则：部件之间不互相调用，只有协调器调用它们。部件不读设备状态。

### 3.1 行为协调器

输入：`OnStateChanged(state)`、`OnEmotion(name)`、`OnToolRequest(move/nod/shake)`、`OnFaceTarget(yaw, pitch)`。全部通过 `Application::Schedule()` 或自己的队列切到同一个任务上处理，避免并发。

头的仲裁，优先级从高到低：

1. 语音指令转头（MCP 工具）
2. 动作（点头 / 摇头）
3. 人脸追踪
4. 保持不动

高优先级结束后，低优先级恢复。任何来源的角度都过同一个限位函数（俯仰保持在官方给的安全范围内）。

状态表：

| 状态 | 脖子 | 脸 | 灯环 | 唤醒 |
|---|---|---|---|---|
| 待机 | 慢速回正中后不动 | `neutral`（眨眼循环），偶尔小动作 | 关 | 开 |
| 听用户说 | 人脸追踪 | `listening` | 绿，常亮 | 开 |
| 她说话 | 追踪关，停在最后位置；可播动作 | 当前情绪动画 | 蓝，呼吸；强情绪用情绪色 | 开（见 5） |
| 连接中 / 配网 | 不动 | 官方默认 | 白，慢呼吸 | 按官方 |

### 3.2 动作触发

- 情绪映射（表驱动，放在一个常量表里）：`happy/laughing/confident → 轻点头一次`，`confused/thinking → 歪头`，`sad/crying → 低头`，`angry/shocked → 快速小幅摇头`。其余情绪不动。
- MCP 工具：`self.head.nod`、`self.head.shake`（参数：次数 1–3）。工具描述里写明“表示同意 / 不同意时调用”。保留官方 `self.neck.*` 三个工具。
- 节流：两次自动动作之间至少 4 秒（常量，可调）。工具调用不受节流限制。

### 3.3 灯环

状态色见上表。情绪色表从旧 fork 的 `UpdateLedsFromEmotion` 搬过来，只保留强情绪（生气红、开心黄、难过蓝、爱心粉）。亮度上限设为 40%，避免电池供电时掉电。

## 4. 人脸追踪

旧 fork 的实现是帧差检测，不认脸，头动时会自激。不搬。

先做验证实验（spike，代码不保留）：在官方板子上接入乐鑫 `esp-dl` 的人脸检测模型，在“听用户说”状态下测三个数：检测帧率、空闲堆内存、语音是否卡顿。

- 通过条件：≥ 3 帧 / 秒，语音无卡顿，内部堆余量不低于 spike 前的安全线（spike 时定数值）。
- 通过 → 方案 A：真人脸检测。取最大的人脸框中心，换算成偏航 / 俯仰增量，低通滤波后交给协调器。连续 2 秒没有人脸 → 头停在原位。
- 不通过 → 方案 B：改进帧差。头在动以及动完后 300 ms 内不检测；只在“听用户说”状态开。
- A、B 都不行 → 对话时头回正中，不追踪。

实现约束：追踪任务优先级低于音频任务；只在“听用户说”状态取帧，其他状态任务挂起。

## 5. 唤醒

代码事实：旧 fork 用 `USE_CUSTOM_WAKE_WORD`（Multinet）。`Application` 在“她说话”状态只保留 AFE 唤醒词（`IsAfeWakeWord()`），在“听用户说”状态默认关闭唤醒（`WAKE_WORD_DETECTION_IN_LISTENING=n`）。推断：这就是“时灵时不灵”。尚未实机确认。

步骤：

1. P0 记基线：官方板子原样固件，三种时候各喊 10 次，记成功次数；同时记 `build.py` 给这块板子选的唤醒词类型和模型。
2. 改配置：`CONFIG_USE_AFE_WAKE_WORD=y`，模型 `nihaoxiaozhi`；`CONFIG_WAKE_WORD_DETECTION_IN_LISTENING=y`。写在板子的 `config.json` 的 `sdkconfig_append` 里。
3. 复测同样的 30 次。验收：每种时候 ≥ 9/10。
4. 如果她自己的声音误触发唤醒（板子不在设备端 AEC 名单里），退路：她说话时关唤醒，改成点屏幕打断。

唤醒词本身不换（用户没要求）。

## 6. 脸和素材

### 6.1 现有素材

用户提供 21 张 PNG（`anan-faces-21.zip`），文件名正好是固件的 21 个情绪名。尺寸 1792×1344 或 1824×1376，都是 4:3。每张带一圈灰色圆角边框，打包时裁掉。角色一致。

边框处理（用户明确要求去掉）：四边各向内裁掉宽度的 8%，保持 4:3，裁完后画面四角都是粉色背景，没有灰边和圆角残留。20 张图自动检测到的内缩量是 7.8%–8.0%；`confused` 自动检测失败，所以全部用固定 8%，不用自动检测。脚本裁完后检查四角颜色，不是背景色就报错。

颜色检查：用户拍的实机照片里（旧 fork 固件），粉色背景显示偏蓝。可能是旧打包脚本红蓝通道反了，也可能只是拍照色差。P5 第一次上机时用 `neutral` 对比原图确认颜色，不对就在管线里修通道顺序。

实测对齐度（缩到 320×240 后与 `neutral` 逐像素比较）：`relaxed`（闭眼）只有 1.3% 像素不同，`surprised`（张嘴）1.2%。其余情绪 4%–12%，身体有轻微位移。

### 6.2 让静态图动起来（不需要新图）

- `neutral`：真眨眼。帧序列 `neutral` ×N → `relaxed` ×2 → `neutral`，循环。
- 说话：`neutral` 和 `surprised` 的嘴部区域交替（只合成嘴部矩形，眼睛不变）。先试效果，不自然就退回下一条。
- 其余情绪：程序生成“呼吸”效果，整张图上下浮动 1–2 像素，4–6 帧循环。不依赖对齐。
- `listening`：用 `neutral` + 呼吸。

### 6.3 管线

`scripts/anan_faces/build_faces.py`：裁边框 → 缩放到 320×240 → 按上面规则生成每个情绪的帧序列 → 转 `.eaf` → 写 `emote.json`（名字、文件、fps、loop）→ 交给官方 `scripts/spiffs_assets/build.py` 打进 assets 分区。

待验证（P5 第一步）：PNG 序列 → `.eaf` 的转换工具。先用 `neutral` 一个动画跑通整条管线并上机，再做其余 20 个。同时测每帧体积，定帧数上限。assets 分区在 16M 分区表里是 8 MB，语音模型和字体也在里面。

原图放 `assets-src/anan/`，随仓库提交。

### 6.4 待机小动作

- `idle_actions` 在待机满 20–45 秒（随机）后挑一个动画播一遍，回 `neutral`。同一个不连播两次。被唤醒时立即停。
- 列表写在 `emote.json` 里以 `idle_` 开头的条目，固件启动时枚举。加新动作不改代码。
- 第一批不需要新图：`idle_sleepy`（`sleepy` 打瞌睡）、`idle_wink`（`winking`）、`idle_delicious`（`delicious` 舔嘴）。
- 喝咖啡、玩手机需要新图：每个动作 3–6 张关键帧，角色和构图与现有 21 张一致。由用户生图，放进 `assets-src/anan/idle_<name>/` 即可。

## 7. 错误处理

| 情况 | 行为 |
|---|---|
| 素材缺某个情绪 | `SetEmotion` 返回 false → 显示 `neutral`，记一条 warning |
| 舵机无应答 | 协调器跳过所有头部命令，其余照常 |
| PY32 不可用 | 灯环命令变空操作，其余照常 |
| 摄像头不可用 | 追踪关，对话时头回正中 |
| 追踪目标超限 | 限位后执行 |

## 8. 测试

- 纯逻辑做主机单测（不依赖 IDF）：头部仲裁优先级、状态表、情绪 → 动作映射、节流、待机计时和不连播规则、限位函数。协调器对硬件只依赖接口，测试里用假实现。
- 素材脚本单测：裁边、尺寸、帧数、`emote.json` 内容。
- CI：每个 PR 跑单测 + 编译 `m5stack/stackchan`。
- 实机验收由用户做，清单见第 10 节。

## 9. 评审流程

按用户的分层流程：PR 前跑测试 / 编译并贴输出 → 新上下文 subagent 审 diff → 发现分 Important / Nit / Pre-existing，逐条修或关 → 单独的安全审查 → PR 模板含 Testing / Risk / How to revert。风险分级：只动板子目录的 PR 为低；动 `application.*`、音频、CI、分区表的为高，需要用户看。评审最多 3 轮。

回滚：每阶段一个合并固件，保留上一阶段的固件文件，回滚就是重烧上一个。

## 10. 阶段和验收

| 阶段 | 内容 | 验收（用户实机） |
|---|---|---|
| P0 | 建仓库；加 stackchan 编译 workflow；原样烧录 | 能对话；官方动画脸正常；记唤醒基线 |
| P1 | 唤醒配置 | 三种时候各 10 次，每种 ≥ 9 |
| P2 | 拆 `servo_neck`；协调器；待机静止；灯环 | 待机 5 分钟舵机零动作；灯色随状态变 |
| P3 | 动作 + 两种触发 | 问是非题，动作和回答一致；不卡语音 |
| P4 | 追踪 spike → 实现 | 左、中、右三个位置说话，头都转向用户；她说话时头不漂 |
| P5 | 素材管线 → 21 个表情 → 待机小动作 | 表情正确且会动；待机能看到小动作；唤醒立即停 |

每阶段结束需要用户烧录并确认，才进入下一阶段。
